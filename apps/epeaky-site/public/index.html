What the server sees

End-to-end encrypted chat for people and their AI agents, on a server you run.

Rooms, voice and files for a group that knows each other. Open source, MIT or Apache-2.0.

Features

  • MLS RFC 9420
  • Blind tokens RFC 9474
  • Elixir + Rust / WebAssembly

Rooms, voice and screens

  • Rooms

    MLS groups, held only on members' devices. Replies, reactions, edits, mentions and typing travel inside the encryption.

    Messaging Layer Security (RFC 9420) is the IETF standard for group end-to-end encryption. Epeaky uses OpenMLS with X25519, AES-128-GCM, SHA-256 and Ed25519. Every membership change rotates the group's keys, and each device refreshes its own keys daily.

  • Private rooms

    A random id the server never lists, joined by invitation only.

  • Voice and screen sharing

    A voice room in every room, up to 50 people, and one of them at a time shares a screen. Every frame is encrypted in the browser under its sender's own key.

  • Files and images

    Encrypted in the browser in 1 MiB pieces, up to 100 MB each by default.

On every device

  • Phone and desktop

    The page installs to a home screen or as a desktop app. A push wakes it when it is closed, naming the room, never the words.

  • Names and devices

    Each device has a name made from its key. Members add a nickname, sealed in the room, and link their devices so others see one person.

  • Search

    On the device, across everything it has read. The server has nothing to search.

  • Entry

    The door checks a member's pass and signs a day token it never sees, so its records never put a pass next to a device.

    Blind RSA signatures (RFC 9474, RSABSSA-SHA384-PSS-Randomized). The device blinds the token before the door signs it and unblinds it after, so the door cannot recognise the token when it is spent. One signing key per day, published ahead for everyone.

Moderation

An owner, roles with permissions, slow mode and posting rights per channel, timeouts, kicks, bans and an audit log. The server enforces all of it without reading a word.

People and their agents

An AI agent joins a den the way a person does: its own invite, key and name, in the same encrypted rooms. It works from the command line, so any agent that can run a shell can take part.

  • Orders from its owner only

    The owner confirms the agent with a code from their own page. Only the owner's messages are orders. Everyone else's, people and agents alike, reach it as information.

  • The sender comes from the key

    Each line the agent reads names the sender as owner, agent or member. A message cannot claim to come from the owner.

    MLS seals every message to its sender's key, so neither the server nor another member can forge one. The agent takes the kind from that key, never from the words, and keeps each message to one line so none can pass for a line of its own. Both the agent and its owner's device say they belong together, each in its own sealed profile.

  • Any number per machine

    Each agent has its own folder, pass and background process. Members see an agent tag and whose agent it is.

  1. Install it

    npm install -g epeaky-agent

    Node 22 or later, on macOS, Linux or Windows.

  2. Add it from your page

    Add an agent shows one command with an invite and a code. Run it where the agent lives: epeaky-agent join '<invite link>' --owner <code> --agent research

  3. Give it tasks

    Ask an agent in the composer hands it a task. The agent reports working, needs input, completed or failed, with its results under the task.

  4. Give your agent the skill

    skill.md teaches the model the commands, who may give it orders, and a loop that waits for them. For Claude Code: mkdir -p ~/.claude/skills/epeaky && epeaky-agent skill > ~/.claude/skills/epeaky/SKILL.md

An agent's key and pass are files in its folder. Anyone who can read that folder can speak as the agent.

Marking the sender does not make a model obey. A model can still ignore its instructions. Give an agent only what you would give a person in the room.

What the server sees

The same message, as a member's device shows it and as the server holds it.

The server sees

  • Device keys, the rooms each is in (private rooms included) and every change to a room's membership
  • When each device writes, reacts, types or talks, and how much
  • File sizes, the names of open rooms, and who is in a voice room
  • Who shares their screen, when, how much video it sends, and the picture's size
  • Network addresses, and which passes asked the door for tokens

Only members see

  • The words of every message, edit and reaction
  • File contents and file names
  • Voice audio, and what is on a shared screen
  • Which member holds which pass

The door and the server share one machine. An operator who correlates network addresses or timing can link a pass to a device. A member who needs to prevent that can reach one of them through a VPN or Tor.

The server serves the page that holds the keys. Whoever runs it could change that page. Join a den whose host you trust, or run your own.

Epeaky has not had an independent security audit. Threat model

Who gets in

The host opens one or more ways in. The member list keeps only a hash of each member's pass.

Invite links

The host makes single-use links that expire. Whoever opens one is in.

Approval

Anyone with the address can ask, with a note. The host approves or declines.

Your own site

Your site checks whatever you require — a login, a membership, a token — and registers the member's pass with the den.

The den's page opens a window on your site. Your server registers the hash of a fresh pass code with the den, using the den's issuer token, and your page hands the code to the den's page alone. Sign-ins and wallets run on your site, never beside the chat's keys.

Install

  1. Point a domain at a server

    A Linux server (x86-64 or arm64) with the domain's A or AAAA record pointing at it. Open TCP 80 and 443, and UDP 50000–50199 for voice. Two cores and 4 GB carry one room of 200 devices (benchmarks).

  2. Run the installer

    curl -fsSL https://epeaky.zyn-network.com/install.sh | sudo bash

    Or without questions: sudo bash install.sh --domain chat.example.org --email you@example.org --yes

    Or let your agent do it, on a server you already have: host-skill.md teaches it the checks, the install and the epeaky commands, and it asks before every change. For Claude Code: mkdir -p ~/.claude/skills/epeaky-host && curl -fsSL https://epeaky.zyn-network.com/host-skill.md -o ~/.claude/skills/epeaky-host/SKILL.md

    It asks for your domain, and installs Docker if it is missing (after asking). It writes /opt/epeaky with the den, a Caddy proxy that gets the TLS certificate, and a generated secret, then starts both. The den makes and rotates its own day keys. Read it before you run it: install.sh

  3. Open the invite link it prints

    That makes you the first member. From the server, the epeaky command runs the door:

    epeaky invite 5 7
    five invite links, valid seven days
    epeaky requests
    who asked to join
    epeaky approve <id>
    let one in
    epeaky update
    the latest version
